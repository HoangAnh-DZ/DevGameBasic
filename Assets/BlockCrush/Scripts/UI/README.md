# Block Crush menus

Open `Assets/Scenes/Home.unity` and press Play. Home is build index 0; Classic gameplay is index 1 and `BlockCrushAdventure.unity` is index 2. Classic opens its existing gameplay. The yellow Adventure button opens the Figma level map. Lucky Wheel, Shop and Calendar open their functional reward, store and Daily views. Challenge currently shows availability information.

Adventure has ten sequential levels in the existing Figma card style, inside a scroll viewport with a fixed header and Play button. The three supplied thumbnail illustrations are reused across the ten dynamic level cards. Fresh progress unlocks level 1; Win unlocks the next level, with level 10 final. Completed levels show a completion mark and their individual Best. Locked entry is rejected in both the map and navigation state.

`AdventureLevels.asset` stores target, move budget and shape-family weights per level. Only successful placements consume moves. Adventure scores one point per placed cell plus line bonuses 10/25/45/70 for 1/2/3/4+ simultaneous lines. Consecutive clears add 5 per prior combo step, capped at 25; no clear resets combo. Rows/columns count once, even when intersecting. The manager's optional `IBlockGameRules` keeps Classic's original scoring, combo, random shapes/colors and Best key unchanged.

Win takes priority over exhausted moves on the final turn and is resolved after clear animation. Lose uses the existing Figma Game Over/Retry controls when moves run out or no available piece fits. Replay/Retry resets board, score, moves, combo and three-piece tray. The tray refills only after all three pieces are consumed, with distinct weighted shapes. Adventure filters new shapes for legal board fits when available, using bounded selection rather than rerolls. The hand appears only during the initial tutorial and disappears after the first accepted placement.

Classic and Adventure both use `GameplayBoosterController` with the existing Figma Bomb, circular-arrow and +1 artwork. Bomb pauses placement while selecting a 3×3 area, clips safely at board edges, and clears occupied cells without scoring. Tap Bomb again to cancel without spending. The circular arrows refresh only the remaining tray slots to different shapes that currently fit, using the current mode's shape weights and retaining colors, used slots and normal refill count. +1 converts the largest waiting piece into a Single 1×1 in the same slot and color; it does not add moves. Placing that piece uses the existing scoring and turn rules. These are the project's chosen mechanics, including making all three useful in Classic as well as Adventure.

Every successful action consumes one saved item through `EconomySave.TryConsumeBooster()`, re-reading durable inventory before spending. Empty/invalid bomb areas, cancel, already-single trays, impossible/no-effect refreshes and unavailable states never spend. Failed refreshes restore the random generator state. All boosters reject active drags, line animations, Settings/information modals, transitions and terminal games. Duplicate callbacks in one frame cannot spend twice. Restart, focus loss and scene unloading cancel targeting; closing selection preserves an open Settings pause. Existing wallet revision updates counters without idle JSON polling. No free inventory is added; collect items from Lucky Wheel or purchase a demo bundle on Home in the Editor.

`BlockCrushBoosterBuilder.Build()` / **Block Crush > Update Gameplay Boosters** selectively wires the two saved gameplay scenes and preserves all other scenes. It also runs after a full menu rebuild. Classic's added toolbar makes visual room below the tray; Adventure retains its artwork position while expanding the transparent touch regions. `GameplayBoosterLayout` fits waiting pieces within their slots so long shapes cannot cover booster touch regions. The original drag code still expands pieces to board-cell size and returns them to their stored presentation scale. `BombTargetInput` maps real mouse/touch coordinates to board cells and owns one pointer at a time. `BlockGameManager.SessionRestarted` only resets booster presentation after the original restart/refill sequence. `BlockCrushMenuVerification.StartBoosters()` tests both saved scenes through their EventSystem; the full `Start()` includes the same booster fixtures and existing regressions.

Adventure saves `BlockCrush.Adventure.HighestUnlocked`, `LevelN.Complete`, `LevelN.Best`, the existing `Completed` key and `TutorialDone`. Existing sequential three-level saves migrate without deletion. Settings pauses/replays; gameplay Back restores the map, and map Back/Escape returns Home. `Editor/AdventureSimulation.cs` runs deterministic legal-play strategies with shared scoring/generation, recording win rate, mean score/moves and loss reasons in `Captures/Figma/AdventureBalance.csv`. Initial targets/moves are retained in `AdventureLevelCatalog.Defaults()`; the saved asset contains measured tuning. Current targets are 120/155/195/235/280/300/335/350/405/425; move budgets remain 22/26/30/34/38/42/46/50/54/58. Simulation heuristics are not measured human difficulty.

Game Over uses the Figma title, background, score panel and Home/Play button artwork. Its score is the actual `BlockGameManager.Score`; Home unloads gameplay, and Play calls the existing `RestartGame()`. Figma has no Best field on this screen, so its legacy text reference is retained but hidden. Best persistence and Game Over detection are unchanged.

All three scenes instantiate `Assets/BlockCrush/Prefabs/SettingsUI.prefab`. Its saved Button listeners and controller references are already wired. Settings pauses interaction and any running line-clear animation. Closing resumes the same game; Replay calls the original `RestartGame()`. Back Home loads a single scene and unloads gameplay.

The preferences `BlockCrush_Sound`, `BlockCrush_BGM` and `BlockCrush_Vibration` default to enabled and save immediately. `GameAudioService` now reuses the original Sound/Music sources plus one bounded SFX accent source. Eight original synthesized mono PCM clips in `Assets/BlockCrush/Audio/SFX` cover placement, clear, multi-clear, combo, invalid drop, click, complete and failure. Clips are preloaded at 22.05 kHz, normalization is disabled and waveform peaks stay below 0.45; two voice gains are capped at 0.55/0.5. Sound OFF stops both SFX voices; BGM remains independent. No music recording was supplied; `PlayMusic(AudioClip)` remains available. Mobile vibration and existing settings callbacks are retained.

Level Complete's left button says Home and uses a cyan material on the existing rounded green sprite, preserving its highlights/shadow. `SceneNavigationController.CompleteHome()` opens Home with the map closed and saves PlayerPrefs. Next keeps its original green sprite, geometry and progression callback. The final Next/Levels behavior and Settings Back-to-map remain unchanged.

`BlockGameFeedback` implements optional presentation hooks and never calculates score/combo. Combo text follows Figma nodes `4:70` (COMBO+2, Lilita One 80px, #85DB0C) and `4:69` (COMBO+4, 88px, #F1C11E), with a black 40% shadow at y=10. The count is dynamic; tiers 2–3 use green, tiers 4+ gold. The generic Combo nodes `4:71` / `4:73` were also inspected. No motion data was returned for `4:70`; the permitted pop/hold/fade lasts 0.85 seconds, replaces the previous text and blocks no raycasts. Combo SFX and the visual start together after the placement pop. Restart/terminal results clear pending effects, and Settings pauses gameplay feedback. [Lilita One](https://github.com/google/fonts/tree/main/ofl/lilitaone) is imported unmodified with its OFL license in `Assets/BlockCrush/Fonts`.

`BlockCrushFeedbackBuilder.Build()` synthesizes/imports the clips and selectively wires the existing prefab and three saved scenes. Integration verification includes Home/Next on all ten levels and actual audio DSP output, Sound/BGM independence, reset/deduplication, font/color, waveform bounds and portrait captures. `BlockCrushMenuVerification.StartFeedback()` runs just the feedback fixtures; the full `Start()` retains Adventure and menu regressions. Test preferences and progression are restored.

More Settings shows `Application.version`. Contact, Share, Terms and Privacy open explicit information callbacks because no public URL, support address, legal content or share provider exists in the project. About describes the implemented game. The cyan icon squares are the actual Figma shapes, not replacement artwork.

Lucky Wheel uses the original transparent Figma disc, rim, pointer, hub, panel and button fills. Existing wheel/bomb/reverse/booster sprites are reused; exact Figma text rotations remain on the moving disc. A fitted Safe Area contains the popup at both portrait resolutions. `BlockCrushWheelBuilder.Build()` updates only Home and the wheel's new assets; menu rebuilding also invokes it. Asset node IDs and methods are in `Captures/Figma/LuckyWheelAssetSources.json`.

`LuckyWheel.asset` holds eight rewards clockwise from the top: 1000 coins, 300 coins, 100 coins, 2 bombs, 50 coins, 150 coins, 2 boosters, 2 reverses. Weights are 2/10/24/6/35/15/4/4; the custom inspector exposes weights, duration and turns while retaining Figma reward identities. One free spin is available per UTC day. `BlockCrush.LuckyWheel.v1` stores the consumed day, immutable pending outcome, sequence, last receipt, recorded count and acknowledged receipt ID. Landing credits the wallet once, then opens Figma's dimmed “You get:” modal with matching artwork/amount, current coin balance and cyan OK. OK acknowledges the notification without awarding again. Interrupted spins and unacknowledged receipts recover on reopen; the last old receipt migrates to the new wallet once. Same-day reopen/restart and clock rollback cannot add a turn.

The wheel reward's entire white frame fits at 90% of the wheel panel's bounds and centers on that panel rather than the full display. `FigmaLayoutFitter.FitInside` follows its actual transformed bounds through screen resizing and safe-area changes. The wheel passes its saved `Panel_7_16502` reference; Daily rewards and Shop confirmations reset to their normal safe-area layout. The OK artwork retains its aspect ratio inside a larger 449 × 236 touch region.

The missing-reward report was reproduced from Unity's log and saved Home: `RewardPopupController.cancel` was null and `ShowReward` dereferenced it before opening the view. Cancel is now guarded for rewards and confirmations; Home has its saved button reference restored. A regression check clears this reference and verifies that the reward opens, acknowledgement runs once, and the wallet stays unchanged.

`EconomySave` stores coins, bomb/booster/reverse counts, Daily progress/claim flags and the last credited wheel identity in a single flushed JSON record. Wheel grants and their idempotency marker share one wallet write; Daily claims atomically update coins and claim flags. Editor uses `BlockCrush.Economy.EditorDemo.v1`, separate from shipping `BlockCrush.Economy.v1`. Gameplay consumes existing inventory through the booster API without changing that save schema or grant/claim rules. Extra spins and rewarded ads remain unavailable. UTC uses local device time, not a server. Three original preloaded mono PCM wheel clips reuse the existing SFX source; Sound applies immediately and BGM stays independent.

Daily Tasks follows Figma's purple/gold frame, five rows, timer, gift/progress, waiting/ready Claim and completed green checks. The user authorized choosing sensible milestones: 2/4/6/8/10 finished Adventure rounds, 100 coins per milestone, reset at 00:00 UTC. Win/loss counts once only after an accepted placement; entering a scene, invalid drops, replaying an unfinished round or quitting never counts. Five claims open the gift lid as a completion indicator; no unspecified bonus payout or ad skip is invented. Rules live in `DailyTasks.asset`.

Shop has separate scrollable Bundles and Items tabs, original Figma awning/cards/ribbons/price buttons and live inventory counters. `Shop.asset` contains Figma's five bundles (4000 coins + 10 of each item, $4.99), Remove Ads ($4.99), booster X1 ($4.99), and coin packs 1000/$0.99, 15000/$9.99, 25000/$14.99, 2000/119.000 ₫. These are Editor measurements, not physical-device density certification.

Verification: `BlockCrushMenuVerification.Start()` runs from Home in Play Mode using synthetic Mouse state events through InputSystemUIInputModule and the EventSystem. The menu builder creates Home and the UI prefab, then adds the prefab and Settings button callback to the existing gameplay scene and rebuilds Adventure. It never invokes the gameplay scene builder. `BlockCrushScreenBuilder.BuildGameOver()` and `BuildAdventure()` update the respective saved screens without rebuilding core gameplay. The core manager/spawner consult optional Adventure rules; Classic retains its original scoring and random-generation branches.

UI update policy: `EconomySave.Save()` increments an in-memory revision only after the existing JSON record is flushed. Wallet and Daily views observe this revision instead of repeatedly deserializing unchanged PlayerPrefs. Keep wallet mutations behind the existing save/claim/grant APIs. Daily and Wheel countdowns use `CountdownText` once per second and still refresh eligibility when the UTC date changes, including clock rollback. Opening a view refreshes its saved state immediately.

Layout components compare their screen, safe-area and parent geometry before applying transforms. `FigmaLayoutFitter` also observes transformed containment bounds and updates its host first during resizing. Public `Apply()` remains an explicit forced refresh. Adventure HUD writes occur only when displayed values change. Board preview reuses its list and skips unchanged highlights after validating placement; occupancy and scoring rules remain in the existing board/manager.

Editor builders share geometry helpers in `UiBuilderUtility`, require Edit Mode with saved scenes, and unload temporary prefab contents in `finally`. Full menu rebuilding reconnects gameplay audio after replacing SettingsUI. `Handheld.Vibrate()` is compiled for Editor/Android/iOS only; the mobile preference check is unchanged. Formatting follows `.editorconfig`; verification counters are excluded from Player builds.

`BlockCrushMenuVerification.StartOptimization()` checks cache invalidation, saved wallet updates, UTC boundaries, translated/resized popup containment, preview allocations and real Adventure HUD changes. The existing full menu and Classic suites remain the gameplay regressions. See `Captures/Figma/OptimizationReview.md` for measured results and scope.
